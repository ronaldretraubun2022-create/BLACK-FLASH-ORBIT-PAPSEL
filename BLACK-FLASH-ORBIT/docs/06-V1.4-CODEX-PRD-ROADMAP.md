# BLACK FLASH ORBIT v1.4 --- CODEX PRD AND PHASE ROADMAP

## Mission

Continue BLACK FLASH ORBIT from v1.3 to v1.4 without breaking existing
functionality. v1.4 is an incremental product expansion on top of the
existing modular monolith, not a rewrite.

## Operating Roles

Codex acts as:

- Principal Software Architect
- Senior Fullstack Engineer
- AI Systems Engineer
- Security Engineer
- Product Architect

## Baseline Contract

The v1.4 entry baseline is:

- Build PASS
- Security PASS
- Newsroom PASS
- Knowledge PASS
- Workflow PASS
- Runtime PASS
- Responsive PASS

Each phase must revalidate the baseline before and after changes. If the
local evidence differs from the claimed baseline, stop feature expansion,
record the blocker, and repair only the affected regression.

## Non-Negotiable Rules

- Preserve all existing modules and public routes.
- Keep `npm run lint`, `npm test`, and `npm run build` passing.
- Keep `npm run test:security` passing.
- Never expose secrets in frontend code, logs, tests, docs, screenshots, or
  generated bundles.
- Keep service-role and provider keys server-side only.
- Maintain authenticated user isolation across caches, APIs, RLS, and UI state.
- Prefer modular monolith boundaries over new frameworks or major rewrites.
- Add dependencies only when the existing stack cannot reasonably solve the
  problem.
- Add or update tests for every behavior change.
- Do not deploy, tag, merge, commit, or push unless explicitly approved in the
  current task.

## Architecture Direction

v1.4 expands existing domains through feature modules, services, and tests:

```text
apps/web/src/
  components/        shared shell, dashboard, command UI
  features/          reusable domain feature widgets
  hooks/             domain data hooks and state coordination
  pages/             route-level screens only
  services/          API clients, caches, and browser-safe adapters

server/
  middleware/        auth, rate limits, errors, request context
  routes/            HTTP contracts per domain
  services/          AI, workflow, observability, security, repositories
  lib/               domain engines and safe utilities

supabase/migrations/
  forward-only schema, RLS, indexes, and ownership changes

tests/
  newsroom/knowledge/security focused regression suites
```

## Phase Roadmap

### Phase 1 --- ORBIT CORE

Scope:

- Unified Dashboard
- Global Search
- Notifications
- Activity
- AI Usage
- Runtime/Health Widgets
- Command Palette

Architecture:

- Keep Command Center as the home surface.
- Reuse existing dashboard telemetry and command palette services.
- Add search/notification APIs only behind authenticated routes.
- Keep widgets data-backed or clearly marked as degraded/empty.

Acceptance:

- Dashboard loads with no blank screen.
- Global search never leaks cross-user data.
- Notifications and activity support loading, empty, error, and retry states.
- AI usage excludes provider secrets and raw prompts.
- Existing Command Palette behavior is preserved.

### Phase 2 --- AI Workspace 2.0

Scope:

- Prompt Library
- Categories
- Favorites
- History
- Variables
- Versioning
- Sessions
- Model Switcher

Architecture:

- Extend the existing prompt/session services.
- Store model/session metadata per authenticated user.
- Keep prompt variables validated before provider calls.

Acceptance:

- Prompt CRUD is owner-scoped.
- Version history is recoverable.
- Model switching is persisted per session.
- Provider failures are recoverable and sanitized.

### Phase 3 --- Intelligence Pro

Scope:

- Semantic Search
- Timeline
- Evidence Graph
- Entity Graph
- AI Investigation

Architecture:

- Build on the existing Intelligence engine.
- Keep extracted entities, claims, source links, and reprocess audit
  owner-scoped.
- Treat AI investigation as draft analysis, not verified truth.

Acceptance:

- Search results cite source evidence.
- Timeline and graph views do not use unsafe HTML.
- Reprocess remains idempotent and source-link aware.

### Phase 4 --- Web Builder Pro

Scope:

- Drag and Drop
- Inspector
- Components
- Responsive Preview
- Theme
- Publish

Architecture:

- Extend existing Web Builder project/page contracts.
- Keep preview/export isolated from executable user scripts.
- Preserve local HTML/ZIP export behavior.

Acceptance:

- Project/page CRUD remains owner-scoped.
- Exported ZIP is runnable.
- Responsive preview covers mobile, tablet, and desktop.
- Publish is gated by explicit readiness state.

### Phase 5 --- AI Newsroom Pro

Scope:

- Editorial Queue
- Fact Checker
- AI Reviewer
- SEO
- Publishing Queue

Architecture:

- Build on Newsroom Prompt Engine v2 and Fact Guard.
- Human approval remains separate from AI review.
- Publishing status changes are auditable.

Acceptance:

- Drafts cannot be marked publish-ready with critical blockers.
- SEO output is source-aware and editable.
- Queue mutations invalidate history caches.

### Phase 6 --- Workflow Automation Pro

Scope:

- Visual Workflow
- Scheduler
- Webhooks
- AI Steps
- Logs

Architecture:

- Extend existing workflow definitions, templates, runs, and approvals.
- Add webhook signature validation before execution.
- Keep AI steps behind approval where required.

Acceptance:

- Runs persist across restart.
- Failure states are visible and recoverable.
- Scheduler and webhook inputs are validated and rate-limited.

### Phase 7 --- Agent Bridge Pro

Scope:

- Repository Scan
- Patch Generator
- Code Review
- Approval Queue

Architecture:

- Keep Agent Bridge local, owner-scoped, and approval-gated.
- Never expose arbitrary shell execution.
- Store safe summaries and bounded changed-file lists only.

Acceptance:

- Repository paths cannot escape the configured repo.
- Generated patches require approval before execution.
- Review output avoids secrets and raw credentials.

### Phase 8 --- Security Center Pro

Scope:

- MFA
- Device Manager
- Session Manager
- Threat Monitor
- Secret Scanner

Architecture:

- Use Supabase Auth capabilities where available.
- Add backend authorization checks for admin/security views.
- Keep secret scanning read-only unless explicit remediation is approved.

Acceptance:

- Admin-only views return 403 for non-admin users.
- Session/device data is scoped to the authenticated user or authorized admin.
- Secret scan findings never print secret values.

### Phase 9 --- Observability

Scope:

- CPU
- Memory
- Database
- AI Provider
- Logs
- Metrics
- Alerts

Architecture:

- Extend health/readiness and runtime telemetry.
- Use redacted structured events.
- Avoid logging full prompts, documents, tokens, or private content.

Acceptance:

- Health remains fast and public.
- Readiness checks durable dependencies.
- Alerts identify safe error codes and affected modules.

### Phase 10 --- ORBIT Operating System

Scope:

- Integrate all modules.
- Final verification: test/build/security PASS.

Architecture:

- Consolidate navigation, permissions, command palette, search, activity, and
  observability across modules.
- Preserve modular domain boundaries.

Acceptance:

- Full regression passes.
- Responsive QA passes at release breakpoints.
- Bundle secret inspection passes.
- No known critical or high issue remains.

## Workflow Per Phase

Each phase follows this sequence:

1. Plan.
2. Analyze existing architecture.
3. Implement minimal modular changes.
4. Preserve existing features.
5. Write or update tests.
6. Run focused tests.
7. Run build.
8. Run security tests.
9. Fix failures only in affected scope.
10. Document changed contracts and decisions.
11. Commit only after explicit approval.
12. Push only after explicit approval.

## Required Output Per Phase

Every phase report must include:

- Analysis
- Architecture
- Folder Changes
- Files Created
- Files Modified
- Complete Code or patch summary
- Tests
- Security Review
- Verification
- Remaining Risks
- Phase Status: PASS or FAIL

## Release Gate

The minimum final gate is:

```powershell
npm run verify
```

If `verify` is unavailable, run:

```powershell
npm run lint
npm test
npm run build
```

Any failure blocks the phase.
